# 计费、充值与订阅

Oproxy 同时提供按量余额和订阅套餐。价格、折扣、限额与模型会变化，请在付款前查看实时页面。

## 先看懂三类数值

| 数值 | 含义 |
| --- | --- |
| 标准费用 | 按模型定价页的标准单价估算的费用，用于对照 |
| 实际费用 | 应用分组、渠道、订阅折扣和计费规则后的最终扣费，以使用记录为准 |
| 余额 / 订阅额度 | 余额用于按量扣费；订阅额度受日、周、月限额和有效期约束 |

## 费用怎么计算

模型可能分别计算输入 Token、输出 Token、缓存写入、缓存读取、图片或按次调用。按 Token 计价时，可以用下面的方式估算标准费用：

```text
输入费用 = 输入 Token ÷ 1,000,000 × 输入单价
输出费用 = 输出 Token ÷ 1,000,000 × 输出单价
缓存费用 = 缓存 Token ÷ 1,000,000 × 对应缓存单价
标准费用 ≈ 输入费用 + 输出费用 + 缓存费用 + 图片/按次费用
```

例如一次请求使用 20,000 输入 Token 和 5,000 输出 Token，则输入部分为 `0.02 × 输入单价`，输出部分为 `0.005 × 输出单价`。再加入缓存、图片等费用后，平台按当前分组和权益结算实际费用。

::: info 以使用记录为准
公式用于预估。不同模型的计价单位、缓存规则、分组倍率和订阅折扣可能不同，最终扣费以 Oproxy 使用记录中的 **实际费用** 为准。
:::

## 按量余额

在 [充值/订阅](https://oproxy.world/purchase) 中切换到 **充值**：

1. 选择快捷金额或输入自定义金额。
2. 选择支付宝或微信支付。
3. 页面显示支付金额后，核对账户和金额。
4. 只有点击 **确认支付** 才会创建付款流程。

![充值页面的金额、支付方式和确认按钮](/images/oproxy-steps/recharge-controls.png)

::: danger 付款确认
不要替他人点击确认支付。订单金额、支付方式和最终价格以付款页面为准。
:::

## 订阅套餐

订阅页显示套餐价格、30 天周期、折扣、倍率、并发/RPM 增强，以及日、周、月限额。可售方案包括“试试水”、Lite、Pro、Coding-Lite、Coding-Pro、Coding-Max、Coding-Ultra 和并发数增强包，具体以页面为准。

订阅余额可获得折扣，但仍按模型调用消耗；先根据历史使用记录估算需求。

![充值订阅页面中的订阅套餐卡片](/images/oproxy-steps/subscription-plans.png)

*图：订阅页展示套餐价格、周期、折扣、并发/RPM 增强及日、周、月限额。具体内容以购买时页面为准。*

## 套餐额度、RPM 与并发

- **日 / 周 / 月额度**：分别限制对应周期内可使用的订阅额度；其中任一限制用完都可能暂时无法继续调用。
- **RPM / TPM**：限制每分钟请求数或 Token 数，决定短时间内能发送多少请求。
- **并发数**：限制同时处理的请求数量，和账户余额不是同一个概念。
- **并发数增强包**：用于提升并发或 RPM 能力，不会替代模型调用费用。

出现 `429` 时，先降低并发并检查 API Key 自身的速率限制。如果正常业务持续达到套餐的 RPM 或并发上限，可在充值/订阅页购买增强包或升级套餐。参见 [错误码与处理](/docs/tokenflux/error-codes.html)。

## 我的订阅

[我的订阅](https://oproxy.world/subscriptions) 展示每个计划的状态、到期时间和每日/每周/每月用量。过期计划仍可能显示历史额度；不要把历史卡片当作当前有效权益。

## 实际费用与标准费用

仪表盘和使用记录同时展示实际费用与标准费用。实际费用反映折扣、分组或订阅后的结算；标准费用用于对照。

## 如何核对一笔费用

1. 打开 [使用记录](https://oproxy.world/usage)，按 API Key 和请求时间筛选。
2. 核对模型、输入/输出 Token、缓存、请求类型和计费模式。
3. 比较标准费用与实际费用，确认是否使用了预期分组或订阅。
4. 再到仪表盘查看同一时间范围的汇总趋势。
5. 对扣费有疑问时，保留请求时间、模型和错误信息并提交工单；不要发送完整 API Key。

## 余额或额度不足

- **按量余额不足**：充值后再请求，并设置余额不足提醒。
- **订阅日 / 周 / 月额度用完**：等待对应周期重置，或升级套餐。
- **订阅已过期**：续订后确认状态已恢复，不要把历史订阅卡片当作有效权益。
- **仍然返回 429**：检查 RPM、TPM、并发数和 Key 速率限制，而不是只看余额。

## 余额提醒

在 **个人资料 → 余额不足提醒** 中可：

- 启用或关闭邮件提醒；
- 设置自定义阈值，留空使用系统默认值；
- 添加并验证通知邮箱。

保存设置会改变账户通知配置，操作前确认邮箱正确。

## 退款提示

用户协议说明，未使用的实际充值余额可申请退款并需身份/交易核验；已消费金额、赠送余额、优惠和部分订阅权益通常不退。请以最新协议和客服核验结果为准。
