# 错误码与处理

调用失败时，先记录请求时间、模型名、Key 名称和错误正文。不要在截图、工单或聊天中发送完整 API Key。

::: info 状态码说明
客户端、Oproxy 网关和上游模型都可能返回错误。相同问题在不同协议中可能使用不同状态码，因此应同时查看 HTTP 状态码、错误正文和 Oproxy 使用记录。
:::

## 快速对照

| 状态或提示 | 常见原因 | 处理方式 |
| --- | --- | --- |
| `401` / 认证失败 | Key 不完整、已禁用、已过期，或认证变量填写错误 | 重新复制 Key，确认状态和有效期；Codex 使用 `OPENAI_API_KEY`，Claude Code 使用 `ANTHROPIC_AUTH_TOKEN` |
| `429` / 请求过多 | RPM、TPM、并发数、订阅限额或单个 Key 的速率限制不足 | 降低并发并稍后重试；检查 Key 限制和订阅用量；持续不足时购买并发/RPM 增强包或升级套餐 |
| `503` / 服务不可用 | 上游模型或渠道暂时不可用、拥塞或维护 | 查看模型监控，等待后重试；必要时切换模型、分组或端点 |
| 审核或封禁 | 请求内容触发审核，或 Key/账户因风险、违规被冻结 | 内容审核时调整输入；Key 或账户被冻结时停止重复请求，查看通知并提交工单申诉 |
| 模型不存在 / 无可用渠道 | 模型 ID 拼写错误，或该 Key 的分组不包含目标模型 | 在模型定价页复制完整模型 ID，并把 Key 切换到正确分组；生产应用建议新建 Key 测试后再迁移 |
| 余额不足 / 额度耗尽 | 按量余额不足、订阅日/周/月额度用完，或订阅已过期 | 查看余额和我的订阅；充值、续订或等待额度重置后再调用 |

## 429：RPM、并发或限额不足

`429` 不一定只表示 RPM 不足，也可能来自 TPM、并发数、订阅额度或 API Key 自身的速率限制。

1. 暂停高并发任务，等待 30–60 秒后重试。
2. 为自动任务使用指数退避并加入随机延迟，不要立即循环重放。
3. 在 API 密钥页检查该 Key 是否设置了速率或额度限制。
4. 在 **我的订阅** 检查日、周、月额度，以及并发/RPM 权益。
5. 如果正常业务持续触发限制，在 **充值/订阅** 中购买并发数增强包或升级到更高 RPM 的套餐。

::: warning 不要无限重试
无限重试会继续占用并发并放大故障。达到重试上限后应暂停任务并记录错误。
:::

## 503：上游模型不可用

`503` 通常表示上游渠道临时不可用，并不代表 API Key 已失效。

1. 打开 [模型监控](https://oproxy.world/monitor)，查看目标模型的状态、延迟和 PING。
2. 等待一段时间后重试，并使用指数退避。
3. 业务允许时，切换到同类模型或其他可用分组。
4. 比较默认端点与国内优化端点，但不要通过反复创建 Key 解决上游故障。

## 审核或封禁

### 内容被审核拦截

如果错误正文提示内容安全、审核、风险或政策限制：

1. 停止重复提交相同内容。
2. 删除或改写可能触发限制的输入、附件或工具参数。
3. 阅读 [内容安全审核告知](/docs/tos/review-notification.html) 和 [使用规范](/docs/tos/usage-policy.html)。

### Key 或账户被冻结

如果 Key 状态显示禁用，或错误正文明确提示封禁：

1. 查看控制台通知、邮件和相关规则。
2. 在使用记录中定位异常请求的时间、模型、费用和 User-Agent。
3. 通过工单提交请求时间、错误正文和必要说明，不提供完整 Key 或密码。
4. 不要通过批量创建新 Key 绕过平台限制。

## 分组不正确

Key 分组决定可访问的模型。常见情况包括：

- GPT / Codex 使用了不包含目标 GPT 模型的分组；
- Claude Code 使用了非 Claude 分组；
- 模型名与模型定价页的完整 ID 不一致；
- 分组已经调整，但客户端仍使用旧配置或旧 Key。

处理时先查看 [密钥分组与模型访问](/docs/tokenflux/composite-key.html)，再创建一个正确分组的测试 Key。最小请求成功后再替换生产配置。

## 余额不足

1. 在仪表盘确认按量余额。
2. 在 **我的订阅** 检查计划是否有效，以及日、周、月额度是否已用完。
3. 在使用记录中查看最近请求的实际费用。
4. 余额不足时充值；订阅额度不足时升级套餐、购买增强包或等待额度重置。

## 提交工单前

按以下顺序收集信息，可减少来回沟通：

- 请求发生时间和时区；
- HTTP 状态码与完整错误正文；
- 模型 ID、请求端点和协议；
- API Key 的名称或末尾少量字符，不提供完整 Key；
- 是否稳定复现，以及已尝试的处理方式。
