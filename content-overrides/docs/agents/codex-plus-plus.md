# 客户端配置与账户安全

把 Oproxy Key 接入 Coding 工具时，客户端安全与账户安全同样重要。

## Key 的存放

- 优先使用环境变量、系统凭据存储或权限受限的配置文件。
- 不要提交 `.env`、`auth.json`、`settings.json` 或客户端导出文件。
- 不要把完整 Key 放入截图、工单、聊天或日志。
- 为每个设备和工具建立独立 Key。

![创建密钥弹窗中的安全限制](/images/oproxy-steps/create-key-dialog.png)

*图：可在创建时设置 IP、额度、速率和有效期限制，降低单个客户端泄露后的影响。*

## Oproxy 账户安全

个人设置页支持：用户名与头像、邮箱绑定状态、密码修改、余额不足提醒、通知邮箱，以及 Google Authenticator 等应用的双因素认证。

修改密码、添加邮箱、启用 2FA 或删除头像都会改变账户状态，应由账户本人操作。新密码至少 8 个字符。

## 泄露处理

1. 立即在 API 密钥页禁用相关 Key。
2. 查看使用记录中的时间、模型、费用、端点和 User-Agent。
3. 创建新 Key，并更新受影响客户端。
4. 确认无依赖后删除旧 Key。
5. 如发现异常消费，提交工单并提供请求时间和可定位信息，不提供密码或完整 Key。

![新建工单弹窗](/images/oproxy-steps/ticket-dialog.png)

*图：工单应描述时间、现象和必要的定位信息，不粘贴完整 API Key。*

## 2FA

启用 2FA 会生成安全绑定流程。妥善保存恢复信息，不要让自动化工具代替本人完成绑定或验证码输入。
